## 如何贡献

### 1. Fork仓库
点击右上角的"Fork"按钮，将仓库复制到您的GitHub账户下。

### 2. 克隆仓库
```bash
git clone https://github.com/您的用户名/prompts.git
cd prompts
```

### 3. 创建分支
```bash
git checkout -b feature/您的功能名称
```

### 4. 进行更改
按照下面的规范进行您的更改。

### 5. 提交更改
```bash
git add .
git commit -m "描述您的更改"
```

### 6. 推送分支
```bash
git push origin feature/您的功能名称
```

### 7. 创建Pull Request
在GitHub上创建一个Pull Request，详细描述您的更改。

## 提示词提交规范

### 文件命名
- 使用英文小写字母和连字符 (-)
- 文件名应简明扼要地描述提示词内容
- 使用 `.md` 扩展名

示例：
- `creative-story-starter.md`
- `code-review-checklist.md`

### 文件格式
每个提示词文件必须包含以下YAML前置元数据：

```yaml
---
title: 提示词标题
category: 主分类
subcategory: 子分类
tags: [标签1, 标签2, 标签3]
difficulty: beginner|intermediate|advanced|expert
target_model: gpt-3.5|gpt-4|claude|gemini|universal
language: chinese|english|multilingual
author: 作者名
date: YYYY-MM-DD
description: 简短描述（不超过100字符）
version: 1.0
---
```

### 内容结构
提示词文件应包含以下部分：

1. **标题**：清晰描述提示词功能
2. **提示词内容**：实际的提示词文本
3. **使用指南**：
   - 使用场景
   - 输入要求
   - 预期输出
   - 使用技巧
4. **示例**：至少一个完整的使用示例
5. **变体与扩展**：相关的变体和扩展提示词
6. **相关提示词**：链接到相关提示词
7. **注意事项**：使用时需要注意的事项
8. **反馈与改进**：鼓励用户提供反馈

### 质量标准
提交的提示词应符合以下质量标准：

1. **清晰性**：提示词应明确、具体，易于理解
2. **实用性**：提示词应解决实际问题，具有实际应用价值
3. **完整性**：提供完整的使用指南和示例
4. **原创性**：避免直接复制他人内容，如需引用请注明来源
5. **格式规范**：符合本仓库的格式和分类规范

## Pull Request流程

### 提交前检查
在提交Pull Request前，请确保：

1. 您已阅读并遵循了上述规范
2. 您的更改不会破坏现有功能
3. 您已测试过您的更改（如适用）
4. 您已更新了相关文档

### Pull Request描述
您的Pull Request描述应包含：

1. 更改的简要概述
2. 更改的原因和背景
3. 如何测试您的更改
4. 相关Issue的链接（如有）

### 审查流程
1. 提交Pull Request后，维护者会进行审查
2. 可能会要求您进行修改或补充信息
3. 审查通过后，您的更改将被合并到主分支

## 代码风格

### Markdown风格
- 使用标准Markdown语法
- 标题层级清晰，不要跳级
- 代码块使用正确的语言标识
- 列表使用统一的格式（- 或 *）

### 文本风格
- 使用简洁、清晰的语言
- 避免使用专业术语，或提供解释
- 保持一致的术语使用
- 使用积极的表达方式
